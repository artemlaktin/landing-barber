---
name: send
description: Отправить сохранённые изменения разработчику на проверку (git push ветки + ссылка на pull request). Используй, когда человек говорит «отправь», «готово, отправляй разработчику», «опубликуй».
---

1. Если есть несохранённые изменения (`git status --short`) — сначала выполни шаги команды `/save`.
2. `git branch --show-current`. Если это `main` — нечего отправлять (всё сохраняется в ветки `edit/...`), объясни это.
3. Покажи, что уйдёт: `git log --oneline main..HEAD` — перескажи простыми словами.
4. Отправь ветку: `git push -u origin <ветка>`. Claude Code попросит подтверждение — это нормально, объясни человеку,
   что это отправка на GitHub. Если push не прошёл из-за входа в GitHub — попроси человека выполнить
   `! git push -u origin <ветка>` (с восклицательным знаком в начале) и войти в браузере, когда попросит.
   В `main` не отправлять никогда.
5. Дай ссылку для создания запроса на проверку:
   `https://github.com/artemlaktin/landing-barber/compare/main...<ветка>?expand=1`
   Объясни: «Откройте ссылку, нажмите зелёную кнопку Create pull request — разработчик получит уведомление.
   В описании можно коротко написать, что поменяли». Предложи готовый текст описания (2–4 пункта, по-русски).
6. Скажи, что после того как разработчик примет изменения, для новых правок нужно написать `/start` —
   он подтянет свежую версию.
