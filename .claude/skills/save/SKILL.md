---
name: save
description: Сохранить текущие изменения в истории проекта (git commit) в отдельной ветке, чтобы к этой версии можно было вернуться. Используй, когда человек говорит «сохрани», «зафиксируй» или закончил правку.
---

1. Посмотри изменения: `git status --short` и `git diff --stat`. Если изменений нет — так и скажи.
2. Перечисли человеку простыми словами, что будет сохранено («новая цена стрижки, фото мастера Влада»).
   Если среди изменений есть то, о чём человек не просил, или файлы `.env` — не сохраняй, спроси.
3. Проверка:
   - всегда `npm run build`; если упала — не сохраняй, объясни проблему и предложи исправить;
   - если менялись `app/components/`, `app/pages/`, `app/assets/`, `public/img/` — ещё и агент `site-checker`
     по затронутым блокам. Серьёзные проблемы — сначала исправить, мелочи — сказать и спросить, сохранять ли.
4. Ветка: в `main` напрямую не сохраняем.
   - `git branch --show-current`. Если это `main` — создай ветку `git switch -c edit/<ГГГГ-ММ-ДД>-<коротко-латиницей>`,
     например `edit/2026-10-21-haircut-prices`. Несохранённые изменения перейдут в неё сами.
   - Если уже в ветке `edit/...` — сохраняй в неё.
5. Коммит только нужных файлов (`git add <файлы>`, не `git add -A`), сообщение на английском, коротко по смыслу:
   `content: update haircut prices`, `layout: bigger booking button on mobile`.
6. Скажи: «Сохранено у вас на компьютере. Когда закончите все правки — напишите /send,
   и я отправлю их разработчику на проверку. На живом сайте они появятся после того, как он их примет».
